# Authentication rate-limit UX

The previous Google flow exchanged the ID token in Auth.js's JWT callback. A backend 429 became `BackendAuthError("rate_limited")`, then `CallbackRouteError`, presenting the generic server-configuration screen. Password login already exposed a safe CredentialsSignin code but displayed only an inline message.

The Google backend exchange now runs in Auth.js's **signIn callback**, after OAuth validation and before session creation. Only the concrete BackendAuthError with code `rate_limited` returns the fixed relative redirect `/login/rate-limited`. Successful backend identity/tokens are assigned to the request-local User passed onward to the existing JWT callback in this adapter-free JWT configuration. The exchange happens once; no global cache or token handoff storage was introduced. Other failures are rethrown through Auth.js's failure path, never classified from message text or generic Configuration/CallbackRouteError codes. If an Auth.js database adapter is introduced later, revisit the User handoff and test it against that adapter.

Credentials keep the existing backend/BackendSignInError classification. The login form navigates to the same cooldown route only for its `rate_limited` result code. OAuth issuer, state and PKCE validation are unchanged and precede this mapping.

The cooldown uses `Date.now()` and an absolute 90-second deadline. Only the numeric deadline is persisted under `sessionStorage["antara.auth.rateLimitUntil"]`. Existing valid timestamps, including expired timestamps, are reused, so refreshing never restarts the timer. Expired storage is cleared when the user clicks Back to login or manually starts another login from the normal form. Invalid stored values are replaced with a fresh deadline. Storage failures use a page-local deadline; refreshing in that restricted-storage case necessarily starts a new page-local cooldown.

The initial button is natively disabled and visibly dimmed. At expiry, a polite status announces readiness and Back to login becomes enabled. It calls `router.replace("/login")`, never browser-back, callback refresh, OAuth signIn or credential submission. No code/state/iss/error/scope/query parameters are forwarded. Countdown updates derive from time rather than accumulated ticks, and the interval is cleaned up on unmount. The timer avoids per-second screen-reader announcements.

Backend 429 responses provide Retry-After, but this UI deliberately uses a fixed 90 seconds. Passing Retry-After through the OAuth redirect is unnecessary for this UX and would add protocol/state complexity. No query parameter can select or shorten the duration. Storage and the page are convenience UX, not authentication enforcement; direct visits/client storage manipulation cannot alter backend limits. Non-rate-limit backend/OAuth errors can still use Auth.js's generic failure screens.

Focused validation: `cd apps/web && ../../node_modules/.bin/playwright test --config playwright.auth.config.ts`; `npm run lint --workspace @antara/web`; Prettier checks on changed files; `git diff --check`. The test configuration uses the web workspace's Next.js binary, loopback-only endpoints, disabled Google credentials, offline fonts and local Chromium. Boundary tests mock backend responses; browser tests exercise real rendering, time, storage, refresh, clean navigation, credential-result mapping and mobile layout. They do not perform live Google OAuth or contact production.

No backend, limiter, schema, environment configuration or OAuth-validation change is part of this patch.

Validation result: 28 focused Playwright tests passed (13 existing backend-auth/OAuth-parser regressions, 10 backend sign-in mapping tests, 5 browser cooldown tests). Web lint/typecheck, changed-file Prettier checks and `git diff --check` passed. Initial test-harness failures were corrected: use the web package's Next.js 15 binary, provide an offline @font-face fixture, pause fake time and await hydration, match Auth.js's trailing callback query delimiter, and allow cold development navigation to compile. No backend suites were run because backend code was untouched.
